## Phase Mission

Define temporary storage, locking and IPC locations/mechanisms. Prefer /run,
XDG_RUNTIME_DIR, secure tempfile primitives, flock/fcntl and native sockets/pipes.
A stale .lock file must never be authoritative lock ownership.

## Temporary Files
Use secure OS primitives (`tempfile` etc.). Predictable names in shared `/tmp` are unsafe.
Define cleanup behavior and crash semantics.

## Locks
Lock ownership must be kernel-mediated where possible (`flock`/fcntl/native coordination).
A lock file path may identify a lock object, but file existence alone is not lock state.

Define blocking/nonblocking acquisition, timeout, cancellation and evidence.

## IPC
Choose Unix-domain sockets/pipes/native D-Bus only according to actual communication
needs. Define permissions and peer identity assumptions. Do not expose TCP merely for
local convenience.

## Native Linux Archaeology Checklist

Investigate only mechanisms relevant to this phase, but understand them before wrapping
them. Candidate sources/mechanisms include:

- `/etc/os-release`, FHS and XDG Base Directory conventions;
- `/etc/passwd`, `/etc/group`, NSS via libc/Python rather than manual parsing where possible;
- UID/GID, real/effective/saved IDs, supplementary groups;
- `getpwnam`, `getpwuid`, `getgrnam`, `getgrgid`, `getgrouplist`;
- PAM/login/session concepts where relevant;
- `/proc/self/status`, `/proc/<pid>/status`;
- file modes, umask, ACLs, sticky/setgid/setuid semantics;
- `stat`, `lstat`, `openat`-style reasoning, `O_NOFOLLOW` where applicable;
- Linux capabilities and capability bounding/ambient sets;
- sudo/polkit only when they are actually appropriate;
- systemd system/user managers;
- `RuntimeDirectory=`, `StateDirectory=`, `CacheDirectory=`, `LogsDirectory=`,
  `ConfigurationDirectory=`, `DynamicUser=`, `User=`, `Group=`;
- systemd credentials where applicable;
- `/run`, `/var/lib`, `/var/cache`, `/etc`, `/usr`, `/opt`, `/home`;
- `$XDG_CONFIG_HOME`, `$XDG_STATE_HOME`, `$XDG_CACHE_HOME`, `$XDG_DATA_HOME`,
  `$XDG_RUNTIME_DIR`;
- systemd-tmpfiles and systemd-sysusers where appropriate;
- Unix sockets, pipes, flock/fcntl, secure temporary files;
- mount points/filesystems when ownership semantics depend on them.

Do not wrap a command-line utility merely because it exists. Prefer stable APIs/native
files/protocols when they provide a cleaner contract.

## Adversarial / Failure Analysis

Treat local filesystem and process state as capable of changing between observation and
mutation. Consider:

1. target path replaced by symlink after planning;
2. parent directory permissions change;
3. target user disappears or is renamed;
4. supplementary group membership changes;
5. caller runs through sudo with misleading environment;
6. service runs with a different HOME than expected;
7. XDG_RUNTIME_DIR is absent or belongs to another UID;
8. stale runtime artifacts survive incorrectly;
9. process crashes while creating/chmodding/chowning;
10. attacker pre-creates predictable temporary path;
11. lock holder dies;
12. two Rebuntu processes race;
13. config becomes unreadable;
14. secret file receives permissive mode;
15. root invocation creates root-owned files in user home;
16. filesystem lacks expected Unix ownership semantics;
17. mount becomes read-only;
18. systemd user manager is unavailable;
19. capability set differs from expected;
20. native observation is unavailable or ambiguous.

For every applicable case specify whether the correct outcome is retry, denial, safe
failure, UNKNOWN, repair, reconciliation, or explicit operator intervention.
