## Canonical Semantic Contract

### Package Architecture

```
PackageMetadata (static spec)
    -> to_dict() / to_json()
    -> metadata serialization
    
Dependency (typed specifier)
    -> name + version + extras + markers
    -> to_pip_specifier() / from_pip_specifier()
    
LockFile (locked state)
    -> packages + hashes
    -> verify_hash(package, content) → bool
    
EnvironmentInfo (runtime state)
    -> python_version + executable + prefix
    -> is_venv() → bool

Directory hashing (reproducibility verification)
    -> compute_directory_hash(directory) → sha256
```

### Request/Response Pattern

**Safety Boundaries Enforced:**
- `frozen=True` dataclasses prevent runtime mutation
- Hash verification returns boolean, not side effects
- No external tool invocation in core module

## Security & Resource Boundary

### Security Controls Implemented

1. **Immutable Definitions**
   - All core types use `frozen=True`
   - Prevents accidental modification of dependencies

2. **Hash Verification Only**
   - `verify_hash()` returns boolean only
   - No mutation or side effects

3. **Path-based Exclusion**
   - Pattern-based exclusions for .git, __pycache__, etc.
   - No hardcoded absolute paths in tests

### Resource Constraints

| Constraint | Value | Rationale |
|------------|-------|-----------|
| Default hash algorithm | SHA256 | Standard for content verification |
| Lock file format | JSON | Human-readable and machine-parsable |

## Remaining Risks

### Evidence-Based Risks

1. **Lock file format may evolve**
   - Risk: JSON schema changes break compatibility
   - Mitigation: Version field in lock file for future-proofing
   - Evidence: Current implementation uses version="1.0"

2. **Hash algorithm selection**
   - Risk: SHA256 may be insufficient for future threat models
   - Mitigation: Algorithm is configurable; can add hash_type field later
   - Evidence: SHA256 is industry standard for content verification

3. **Path normalization in hashing**
   - Risk: Different paths to same file may produce different hashes
   - Mitigation: Relative paths used with sorted ordering
   - Evidence: `path.relative_to(directory)` ensures consistent paths
