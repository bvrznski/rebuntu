## Native/Linux Infrastructure Assessment

### Linux Facilities Leveraged

1. **Python tempfile module**
   - Temporary directory creation with unique names
   - Automatic cleanup patterns via context managers

2. **Python subprocess module**
   - Provider execution with timeouts
   - Output capture and truncation

3. **Python pathlib.Path**
   - XDG-style directory tree management
   - Path manipulation in safe temp locations

4. **Unix domain sockets (via os.unlink)**
   - Temporary socket file creation and cleanup
   - IPC testing without live daemon

5. **Python dataclasses with frozen=True**
   - Immutable test result structures
   - Safe sharing across test components

### Not Used (Intentionally)

1. **Docker containers** - Test fixtures don't require containerization
2. **Ansible playbooks** - Testing infrastructure is Python-based
3. **Systemd units** - Temporary environments don't need process supervision

## Canonical Semantic Contract

### Testing Infrastructure Architecture

```
TempRoot (managed temp directory tree)
    -> path: Path  # Root temporary directory
    -> xdg_cache_home, xdg_config_home, etc.
    -> create_xdg_structure()
    
temp_xdg_tree(namespace) -> Generator[dict[str, Path]]
    # Yields XDG-style paths for test isolation

fake_unix_socket(path=None) -> Generator[str]
    # Provides socket path for IPC testing
    
ProviderExecutor(default_timeout=30.0)
    -> run(command, timeout, max_output_size)
       Returns: {"outcome": ..., "stdout": ..., "evidence": [...]}
    
IntegrationMarker
    -> docker_available() -> bool
    -> ansible_available() -> bool
    -> semantic_provider_available() -> bool
    -> host_mutation_allowed() -> bool
    
AdversarialTestCase (base for failure scenarios)
    -> run() -> dict  # Returns outcome with evidence
    
TimeoutScenario, MissingDependencyScenario, etc.
    # Concrete adversarial test implementations
```

### Request/Response Pattern

**Safety Boundaries Enforced:**
- All paths under temp root are safe to create/delete
- Provider execution has timeouts and output limits
- Integration markers don't modify host by default
- Adversarial tests can simulate failures without real system impact

## Security & Resource Boundary

### Security Controls Implemented

1. **Temporary Root Isolation**
   - All test files created under temporary directory tree
   - Cleanup on context exit prevents file accumulation
   - No live filesystem mutation in normal tests

2. **Provider Execution Safety**
   - Timeout enforcement prevents hung processes
   - Output size limits prevent resource exhaustion
   - Evidence collection for traceability

3. **Integration Markers (Opt-in)**
   - Docker/Ansible tests require explicit opt-in via markers
   - `REBUNTU_ALLOW_HOST_MUTATION` environment variable required for host mutations

4. **Adversarial Testing Safety**
   - Failure scenarios are simulated, not actual attacks
   - No privileged operations in adversarial tests

### Resource Constraints

| Constraint | Value | Rationale |
|------------|-------|-----------|
| Default timeout | 30s | Prevents hung processes |
| Max output size | 65KB | Prevents memory exhaustion |
| Temp directory cleanup | Automatic on exit | Prevents disk accumulation |

### Key Design Decisions

1. **Context Manager Pattern**
   - Used for all resource management (temp dirs, sockets)
   - Ensures cleanup even on test failure

2. **Fast Timeout Simulation Mode** (`use_fake_timeout=True`)
   - Skips actual `sleep()` calls in tests
   - Reduces test runtime from 7s+ to ~1.2s
   - Still validates timeout handling logic correctly

3. **Optimized Missing Dependency Check**
   - Default `check_exists_only=True` uses `shutil.which()`
   - Avoids subprocess call for simple existence check
   - Subprocess path available when full error scenario needed

4. **Non-frozen Dataclass Base**
   - Removed `frozen=True` from AdversarialTestCase (changed to `frozen=False`)
   - Allows child classes to set additional instance attributes
   - Critical for TimeoutScenario and MissingDependencyScenario flexibility

5. **Frozen Dataclasses for Results**
   - TestResult still uses frozen=True for immutability
   - Safe sharing across test components

## Rejected Alternatives

### Alternative 1: Use pytest fixtures directly
**Rejected because:**
- Phase 3.12 establishes Rebuntu-level testing patterns
- Separate module allows reuse outside pytest context
- clearer ownership and documentation

### Alternative 2: Implement fake providers with Docker
**Rejected because:**
- Adds unnecessary dependency for testing infrastructure
- Python subprocess is sufficient for most cases
- Can integrate Docker later if needed

### Alternative 3: Global temp directory with manual cleanup
**Rejected because:**
- Risk of leftover files between tests
- Context manager pattern is safer and more explicit

### Alternative 4: Keep frozen=True on AdversarialTestCase
**Rejected because:**
- Child classes couldn't set additional instance attributes
- TimeoutScenario needed `cmd`, `timeout_seconds`, and `use_fake_timeout` as separate fields
- MissingDependencyScenario needed `executable` and `check_exists_only`
- Changed to `frozen=False` to enable flexible initialization

## Remaining Risks

### Evidence-Based Risks

1. **Test fixture cleanup failures**
   - Risk: Test directories not cleaned up on exception
   - Mitigation: try/finally in context managers
   - Evidence: `temp_xdg_tree` uses explicit finally block

2. **Adversarial tests may be too lenient**
   - Risk: Tests may pass without actually catching failures
   - Mitigation: Test actual execution behavior, not just output parsing
   - Evidence: TimeoutScenario with real mode validates timeout behavior

3. **Fast simulation may mask issues**
   - Risk: `use_fake_timeout=True` doesn't exercise real subprocess behavior
   - Mitigation: Include both fast and real modes in test coverage
   - Evidence: 6 tests cover both modes
