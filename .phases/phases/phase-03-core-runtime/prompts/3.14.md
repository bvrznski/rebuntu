## Canonical Semantic/Provider Contract

### Request Flow

```
User/System Input
    -> Deterministic acquisition/normalization (typed request)
    -> Validation (schema, policy, authorization)
    -> Provider selection (capability-driven, native-first)
    -> Provider execution (bounded, timeout-enforced)
    -> Observed output/state (structured result)
    -> Verification (postcondition check)
    -> Evidence collection
    -> Typed result (outcome + verification status)
```

### Provider Selection Rules

| Policy | Behavior |
|--------|----------|
| NATIVE_FIRST | Prefer native Linux mechanisms |
| ALLOW_EXTERNAL | All providers considered |
| EXTERNAL_ONLY | Only non-native providers |

### Result Structure

```python
@dataclass(frozen=True)
class Result:
    outcome: SUCCESS | FAILURE | TIMEOUT | CANCELLED | INVALID_RESULT
    output: Any  # May be None
    evidence: List[Observation]
    verification: VERIFIED | FAILED | UNVERIFIED
```

### Evidence-Based Risks

   - Mitigation: Discovery happens lazily in select_provider()
   - Evidence: `discover_providers()` only called when needed
   
2. **Cache staleness**
   - Risk: Provider state may change between selection calls  
   - Mitigation: 60s cache TTL forces periodic refresh
   - Evidence: Cache invalidation checks timestamp

3. **ONTOLOGY.md header violates project identity**
   - Risk: May cause confusion about Rebuntu versioning
   - Mitigation: Defers to Phase 3.14+ for correction
   - Evidence: Header line contains "REBUNTU 2"
