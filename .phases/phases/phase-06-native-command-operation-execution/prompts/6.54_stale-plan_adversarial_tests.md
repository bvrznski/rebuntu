# C++-Native Command, Operation & Execution System

You are implementing Phase 6 after the clean C++-native restart and Phases 1–5.

HARD INVARIANTS

- The project is Rebuntu. There is one Rebuntu.
- Rebuntu is C++-native.
- C++ owns authoritative deterministic runtime, state, control, typed commands, operation planning, execution, verification, recovery, native providers, IPC and security/policy enforcement seams.
- Python is allowed only at explicit, narrow, justified semantic/ML/research/testing/development boundaries.
- Do not recreate historical Python Runner, Controller, Resolver, command dispatcher, executor, action manager or shell orchestration beneath C++.
- Architecture defines source ownership; language does not define architecture.
- Search the repository before implementation.
- Extend/refactor/compose existing Phase 0–5 structures before adding new ones.
- Command != shell command.
- Intent != command.
- Command != operation.
- Operation != plan.
- Plan != authorization.
- Execution != verification.
- Successful process exit != successful system change.
- Context != authority.
- Provider availability != authority.
- DATA != CONTROL.
- MODEL OUTPUT != AUTHORITY.
- UNKNOWN != PASS.
- Native providers provide mechanisms; canonical policy/authorization owns permission.
- Consequential mutation must converge toward:
  intent/request → resolve target/capability → observe → plan → validate → authorize → execute → verify → record.
- Never allow arbitrary model/user/remote text to become a privileged shell command.
- Prefer direct native APIs/providers to CLI wrappers.
- If an external executable is legitimately required, invoke it argv-style through the canonical bounded process primitive.
- No `system()`, `popen()`, `/bin/sh -c`, `bash -c` or dynamically generated shell pipelines for authoritative operations.
- No destructive host/Git/filesystem cleanup as an implementation shortcut.
- No giant CommandManager/ActionManager/Executor/Controller or universal stringly-typed dispatcher.
- Concurrency must be bounded and cancellation/shutdown deterministic.
- Caller migration must reach a fixed point whenever an old execution path is replaced.
