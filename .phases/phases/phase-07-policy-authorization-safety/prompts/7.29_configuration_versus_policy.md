# C++-Native Policy, Authorization & Safety Foundation

You are implementing Phase 7 after the clean C++-native restart and Phases 1–6.

HARD INVARIANTS

- The project is Rebuntu. There is one Rebuntu.
- Rebuntu is C++-native.
- C++ owns authoritative deterministic runtime, state, control, policy enforcement, authorization mechanics, safety gates, native integration, IPC, execution, verification, reconciliation and recovery.
- Python is permitted only at explicit, narrow, justified semantic/ML/research/testing/development boundaries.
- Do not recreate historical Python policy engines, permission managers, controllers, authorization decorators or safety wrappers beneath C++.
- Architecture defines source ownership; language does not define architecture.
- Search the repository before implementation.
- Extend/refactor/compose existing owners before adding parallel structures.
- Authentication != authorization.
- Authorization != capability availability.
- Privilege != integrity.
- Context != authority.
- Association != authority.
- Plan != authorization.
- Model confidence != authority.
- DATA != CONTROL.
- UNKNOWN != PASS.
- Denial/clarification/required-approval are first-class outcomes.
- Policy decisions must bind to the exact operation, target, relevant context/freshness and plan where consequential.
- Authorization must occur after sufficient deterministic resolution/validation and before consequential effects.
- Providers do not authorize themselves.
- Privileged helpers do not authorize themselves.
- Semantic/model components may propose or annotate; they cannot grant authority.
- Do not implement the complete later Phase-47 OS Task Policy System or Phase-53 Mandatory Security System prematurely.
- Build foundations that later phases can strengthen without bypass or architectural replacement.
- No arbitrary shell authority.
- No destructive host/Git/filesystem cleanup.
- No giant PolicyManager/SecurityManager/GodController.
- No hidden allow-on-error/fail-open behavior for consequential operations.
- Security-critical UNKNOWN defaults to non-execution.
- Caller migration must reach a fixed point when replacing authorization paths.
