# Rebuntu — Phase 8
# C++-Native Privilege Boundary & Secure Execution System

You are implementing Phase 8 after the clean C++-native restart and Phases 1–7.

HARD INVARIANTS

- The project is Rebuntu. There is one Rebuntu.
- Rebuntu is C++-native.
- C++ owns authoritative deterministic runtime, state, control, authorization enforcement, privileged execution mechanics, native OS integration, IPC, verification, reconciliation and recovery.
- Python is permitted only at explicit, narrow, justified semantic/ML/research/testing/development boundaries.
- Privilege != authorization.
- Privilege != integrity.
- Authentication != authorization.
- Provider availability != authority.
- Context != authority.
- DATA != CONTROL.
- MODEL OUTPUT != AUTHORITY.
- UNKNOWN != PASS.
- Root is an execution mechanism, not a trust level.
- A privileged helper must never become a general-purpose root shell or second control plane.
- Every privileged effect must be a typed, validated, narrowly scoped operation.
- Authorization must be bound before privileged execution and revalidated where required.
- Privileged components must independently validate the exact request they receive.
- Do not trust a caller merely because it is another Rebuntu process.
- Do not accept arbitrary command strings, scripts, shell fragments, environment-controlled executables or generic filesystem mutation requests at privileged boundaries.
- Prefer direct syscalls, D-Bus, netlink, ioctl, libsystemd, libudev and other appropriate native mechanisms.
- Use Linux capabilities, polkit and systemd sandboxing where they narrow privilege correctly.
- Do not grant broad capabilities/root merely to simplify implementation.
- No `system()`, `popen()`, `bash -c`, `sh -c` or equivalent privileged shell execution.
- No destructive host changes merely to test the architecture.
- No giant PrivilegeManager/SecurityManager/root daemon.
- No long-lived privileged process unless actual requirements justify it and its attack surface is minimized.
- No secret material in logs, generic IPC, diagnostics or semantic/model context.
- All IPC/messages must be bounded and malformed input must fail safely.
- Caller migration must reach a fixed point when replacing legacy privilege paths.
