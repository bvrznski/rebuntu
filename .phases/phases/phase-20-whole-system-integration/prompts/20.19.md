# Rebuntu --- Phase 20.19 --- Release Readiness Audit

## Agent Task

Execute this as a full standalone repository-aware closure/hardening
task. Perform archaeology, audits, implementation fixes, adversarial
testing, integration verification, documentation and evidence-backed
closure. Do not reduce this to a checklist-only report; fix defects that
are in scope.

## Phase Mission

Apply explicit evidence-backed release gates across correctness,
security, stability, performance, migration, documentation and
operational recoverability.

## Global Agent Contract

Implement **Rebuntu** only.

Phase 20 is closure, not a license to redesign everything again.

The goal is to prove that the architecture built in Phases 0-19 is one
coherent system:

    Interfaces
      -> deterministic / semantic interpretation
      -> typed Request / IR
      -> capability / object resolution
      -> authorization + policy
      -> Operation / Workflow
      -> Runtime
      -> native Linux provider
      -> Observation
      -> Verification / Evidence / Result

with orthogonal long-running behavior:

    Events -> Automation
    Failure -> Recovery
    Desired + Observed -> Reconciliation
    Missing capability -> Controlled Extension

The closure laws:

ONE CONCEPT -\> ONE CANONICAL MEANING. ONE RESPONSIBILITY -\> ONE
CANONICAL MECHANISM. ONE EFFECT -\> ONE AUTHORIZED EXECUTION PATH.
NATIVE LINUX FIRST. OBSERVE BEFORE MUTATE. PLAN BEFORE CONSEQUENTIAL
MUTATION. VERIFY AFTER MUTATION. EVIDENCE SURVIVES FAILURE. UNKNOWN IS
HONEST. NO HIDDEN PRIVILEGE. NO MODEL-TO-SHELL AUTHORITY. NO BLIND
RETRY. NO BLIND RECONCILIATION. NO DESTRUCTIVE CLEANUP AS "MAINTENANCE".
NO DUPLICATE CONTROL PLANES. NO RELEASE CLAIM WITHOUT TEST EVIDENCE.

Do not "clean up" by deleting unknown historical/current code blindly.
Classify, migrate, quarantine/deprecate, test, then remove only when
proven safe and explicitly within repository scope.

Do not mutate unrelated host state during ordinary closure tests.

Phase 20 must fix defects it finds when reasonably in scope. An audit
that merely produces a list of known violations is not completion.

Prefer deleting accidental abstraction/mechanism over adding adapters
around two competing systems.

Preserve the project identity: Rebuntu.

## Duplicate Mechanism Elimination

Search for parallel: executors/runners/dispatchers; event loops/buses;
schedulers/timers; locks; state databases/files; registries/catalogs;
provider resolution; config loaders; observers/monitors; evidence
stores; authorization checks; retry engines; workflow engines;

A duplicate may be legitimate only if semantics/lifecycle/authority
truly differ.

Do not preserve duplicates because migration is inconvenient.

Do not remove code until consumers are mapped and tests prove
replacement.

## Native-Linux Substitution

Audit custom code against: systemd
supervision/activation/timers/scopes/slices; journald; D-Bus; udev;
netlink; inotify/fanotify; pidfd/signalfd/timerfd/eventfd;
procfs/sysfs/configfs; cgroup v2; namespaces/capabilities/seccomp;
native package/network/audio/Bluetooth/display providers.

Replace homegrown mechanism where native authority is clearer, safer and
simpler.

Do not descend to syscalls/ioctl when a stable higher-level native
interface is appropriate.

Record rejected native substitutions too.

## Startup, Readiness and Shutdown

Test: cold boot/service start; user manager absent/present; dependencies
delayed; optional provider absent; semantic provider absent; network
absent; GPU provider absent; stale runtime directory; unclean previous
shutdown; concurrent activation.

Readiness != process running.

Shutdown: stop accepting new work; cancel/drain according to policy;
persist only required semantic state; release locks/resources; flush
bounded evidence; terminate children/providers; leave no orphan work.

SIGKILL/crash path must reconstruct safely on next start.

## Failure Propagation

Inject failures at each boundary.

A low-level failure should retain: source; typed error; subject;
operation/execution identity; attempt; evidence; causal/correlation
context where known.

Do not: turn every error into generic RuntimeError; swallow provider
stderr; convert UNKNOWN to success; retry indefinitely; escalate
privilege; restart unrelated services.

Test partial workflow effects, cancellation, timeout, provider loss,
verification failure, event loss and stale observation.

filenames; hostile logs/events; semantic prompt injection;

## Crash and Fault Injection

Crash at: before plan persistence; after checkpoint; before mutation;
during mutation; after mutation before verification; after verification
before result persistence; during workflow branch/join; during
rollback/compensation; during recovery; during reconciliation.

On restart: reconstruct; reobserve; classify uncertain effects; never
blindly repeat unknown destructive mutations.

Fault sources: systemd/provider unavailable; D-Bus disconnect; disk
full; read-only filesystem; permission denied; timeout; event
loss/duplication; network flap; GPU reset; NVMe disappearance fixture;
corrupt config/state; clock jump; OOM/cgroup pressure.

Use fixtures/sandbox/test host. Do not induce dangerous real-host
failures by default.

## Required whole-system pressure scenarios

### Install to verified operation

Fresh test environment installs Rebuntu, invokes a canonical operation,
observes and verifies the effect, then cleanly uninstalls owned
artifacts.

### Deterministic shell path

`status gpu` resolves without semantic-model invocation and returns
structured plus human output from the same canonical observation.

### Semantic safe path

Natural-language request becomes typed IR, resolves canonical
subject/capability, passes policy and never exposes model-to-shell
authority.

### Workflow partial failure

Multi-step workflow mutates one step then fails; evidence,
compensation/rollback and final state remain coherent.

### Automation storm

Thousands of equivalent events trigger bounded coalesced automation
rather than thousands of executions.

### Hard reboot diagnosis

Previous-boot fixture contains GPU/storage/systemd evidence; Phase
5/8/12 produces bounded causal hypotheses and recovery decision without
invented certainty.

### Recovery versus reconcile

Recovery hold temporarily changes state and Phase 19 does not fight it;
after release, fresh state is reconciled once.

### Capability gap

Phase 17 asks for unsupported action; Phase 18
searches/compose/native/provider paths before candidate extension.

### Security injection

Hostile filename/log/config/model output attempts privilege laundering
and remains inert through all layers.

### Provider loss

Native/provider dependency disappears mid-operation; typed failure
propagates, uncertain effect is reobserved, no blind fallback occurs.

### Crash after mutation

Runtime dies after effect but before result persistence; restart
verifies current state before any retry.

### Long soak

Accelerated month of events/automation/maintenance/reconciliation shows
bounded memory, FDs, evidence and no oscillating control loops.
