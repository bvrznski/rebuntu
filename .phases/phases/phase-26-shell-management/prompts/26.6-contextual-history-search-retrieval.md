# Phase 26.6 — Contextual History Search & Retrieval

## Mission

Implement typed history retrieval by command text, cwd, project, environment, session, execution scope, time, status and duration with privacy-aware filtering.

## Non-negotiable architecture and invariants

Rebuntu is the project name; do not rename or version-brand it. Begin with repository-wide discovery. Existing working structures must be reused, extended, refactored or migrated before creating parallel implementations. Apply **aggregational morphing**: as Rebuntu matures, converge related structures into clearer canonical ownership rather than accumulating bolt-on layers.

The intended boundary is:

```text
human terminal -> Fish
console        -> Bash child -> exit -> Fish
scripts        -> shebang-selected interpreter
coding agents  -> Bash/POSIX shell
systemd/Docker -> their declared interpreter/runtime
```

Do **not** use `chsh` merely to make Fish interactive. Do not replace `/bin/sh`, `/bin/bash`, script shebangs, systemd shell behavior or agent automation with Fish. The graphical terminal may explicitly launch Fish while the account login shell remains conservative.

Phase 26 manages shell state and shell-facing integrations. It does not own the terminal emulator (Phase 27), development project semantics (Phase 28), generic configuration semantics (Phase 36), secrets (Phase 37), identity (Phase 38), or arbitrary process/service control. Integrate with those owners when present.

The selected human-facing baseline is Fish + Oh My Fish + Zephyr. Prefer mature stock tooling over custom Fish code. Preserve Fish autosuggestions, syntax highlighting, completions and history behavior unless a Phase 26 integration intentionally supersedes a specific part.

The current shell-facing tool set to discover/integrate, not blindly reinstall, includes `grc`, `fzf`, `bat`/`batcat`, `fd`/`fdfind`, `ripgrep`, `zoxide`, `btop`, `direnv` and `tldr`. `eza` is intentionally excluded. GNU `ls` remains canonical. For colored listings prefer native `--color=auto`, `dircolors`/`LS_COLORS`, native `tree -C` where appropriate, and selective `grc`; never pollute redirected/machine output with forced ANSI.

Powerline chevrons/separators are abandoned and must not be reintroduced. If shell UI code needs glyphs, restrict it to the already verified set:

```text
FILES:              
NAVIGATION:                     ➜  ❯
SHELL/STATUS:             
SYSTEM:                       
DEV:                
GIT/STATE:      ↑  ↓  +  !  ?  ✘
```

Never assume `bat` vs `batcat` or `fd` vs `fdfind`; discover binaries at runtime. Do not assume distro package versions provide every upstream integration.

History is not surveillance. Capture completed command-level metadata only where justified; do not implement arbitrary keystroke recording. Sensitive material must be redacted/excluded before persistence, indexing, display, export or semantic processing. UNKNOWN is not PASS.

No destructive cleanup is permitted merely because configuration is old, duplicated or misplaced. Back up before mutation; migrate consumers first; delete obsolete material only when the task explicitly authorizes it and evidence proves it is superseded. Conventional Bash recovery must remain available even if Fish, OMF, a plugin, history backend or Phase 26 itself is broken.


## Phase-specific implementation requirements

Implement composable history queries with text/fuzzy capability, time range, cwd/path scope, project, venv, session, shell, status, duration and SYSTEM/VENV scope. Exact filters must remain exact even if a fuzzy frontend is used. Return provenance and redaction status with results. Add pagination/bounds for large histories.

## Required implementation method

### 1. Discover before designing
Inspect the actual repository and the live/user configuration surfaces relevant to this task. Search for existing Phase SHELL work, Fish configuration, OMF/Zephyr setup, functions, abbreviations, aliases, history hooks, fzf/zoxide/direnv integrations, `console`, PATH manipulation, `LS_COLORS`, CLI wrappers, shell/session models, backup/recovery code and any Phase 25 integration. Produce a concise ownership map before editing.

Do not assume a path exists because this prompt names a concept. Follow the repository's established package/tree conventions and AGENTS.md instructions.

### 2. Establish canonical ownership
For every touched behavior, identify:
- authoritative provider/source;
- Phase 26 representation;
- configuration owner;
- read path;
- mutation path;
- recovery path;
- consumers.

If two existing implementations overlap, choose/refactor toward the better canonical structure and migrate consumers rather than adding a third.

### 3. Typed shell-management contracts
Use explicit typed objects/interfaces for the task's domain. Preserve provenance and capability availability. A backend lacking a field must return unsupported/UNKNOWN rather than fabricate a value.

The canonical command-history shape should remain compatible with:

```text
CommandRecord
├── command
├── timestamp
├── cwd
├── session_id
├── shell
├── exit_status
├── duration
├── execution_scope
│   ├── SYSTEM
│   └── VENV
├── environment
│   ├── venv_id
│   ├── venv_name
│   ├── venv_path
│   ├── project
│   └── selected environment fingerprint
└── provenance
```

SYSTEM and VENV are filtered/contextual views over a unified history abstraction, not two unrelated databases.

### 4. Mutation discipline
Any configuration-changing operation must follow:

```text
observe -> diff/plan -> validate -> backup -> authorize as required
        -> atomic/minimal apply -> verify -> record
```

Preserve comments and unrelated user configuration where practical. Never replace an entire configuration file when a minimal owned patch suffices.

### 5. Compatibility and failure behavior
Test both interactive Fish and conservative Bash paths. Shell startup must fail open toward recoverability, not trap the operator in a broken managed environment. Optional integrations must degrade individually.

### 6. Tests and evidence
Add repository-appropriate unit/integration/fixture tests. Prefer temporary HOME/config/history directories for mutation tests. Do not destructively test against the operator's real history or shell configuration.

### 7. Documentation
Document ownership, provider/backend boundaries, user-visible behavior, migration, backup/recovery and exact verification commands. Keep docs synchronized with implementation rather than writing aspirational interfaces that do not exist.


## Global acceptance criteria

The phase is complete only when:
- repository-first discovery and an ownership map were produced;
- existing relevant implementations were reused/refactored/migrated before new ones were added;
- Fish remains the human interactive shell experience and Bash/POSIX compatibility remains intact;
- `console` enters a normal child Bash and `exit` returns to Fish;
- the account login shell is not changed merely for UX;
- OMF/Zephyr and optional tools fail independently rather than breaking recovery;
- shell/history/session/environment/config objects have explicit provenance;
- sensitive commands/variables do not leak into ordinary indexes, logs, UI, exports or semantic contexts;
- no eza or Powerline-separator dependency is reintroduced;
- GNU listing/color behavior remains conventional and redirect-safe;
- configuration mutations are backed up, minimal, validated and verified;
- UNKNOWN/unavailable provider state is explicit;
- tests use safe fixtures where mutation/failure injection is involved;
- Phase 26 remains usable without Phase 25 Panel;
- conventional Bash recovery works if Phase 26/Fish/OMF/history providers fail;
- the final report names files changed, structures reused/moved, tests run, unresolved UNKNOWNs and follow-up work.
