# Phase 37.20 — Secret Cache Boundary

## Mission

Avoid broad plaintext secret caches; where unavoidable, require explicit bounded lifetime and zero general persistence.

## Non-negotiable architecture and invariants

The project is always **Rebuntu**. Begin with repository-first discovery and obey applicable AGENTS.md/tree rules. Search for existing keyring, credential, token, SSH, LUKS, Wi-Fi/VPN, repository-auth, environment-secret, redaction and configuration-secret code before adding anything. Reuse, refactor and migrate first. Apply **aggregational morphing**.

Phase 37 is **not a custom password manager or vault**. It owns generic secret identity, opaque references, provider capability discovery, access policy, safe delivery boundaries, redaction and lifecycle coordination. Native secure providers retain custody of secret material.

Mandatory distinctions:

```text
SECRET REF != SECRET VALUE
SECRET METADATA != SECRET MATERIAL
SECRET IDENTITY != USER IDENTITY
AUTHENTICATION != AUTHORIZATION
AVAILABLE != AUTHORIZED TO RESOLVE
PROVIDER CAPABILITY != PERMISSION
ROTATION != SIMPLE REPLACEMENT
REVOCATION != DELETION
EXPIRED != REVOKED
NOT FOUND != ACCESS DENIED
ORPHAN CANDIDATE != SAFE TO DELETE
REDACTED DISPLAY != SAFE PERSISTENCE
```

The generic data plane must remain value-blind. `SecretRef` may contain provider identity, opaque secret identifier, scope/type, safe metadata and lifecycle status, but never the credential value.

Secret material must never enter:
- general logs or journaling payloads;
- generic audit records;
- configuration diffs/history/snapshots;
- Phase 39 timeline payloads;
- Panel DTOs;
- general CLI inspect/search output;
- search indexes or embeddings;
- semantic-model prompts/context;
- agent reasoning traces;
- crash diagnostics or debug dumps under Rebuntu control.

Redaction is structural and occurs **before serialization/persistence/indexing/export**, not merely by replacing strings in UI output.

Never fall back to plaintext files/environment/configuration merely because a secure provider is missing, locked or unavailable. Provider unavailability becomes explicit UNKNOWN/UNAVAILABLE and blocks unsafe operations.

Resolved material, when an authorized action genuinely requires it, crosses only a narrow consumer boundary, for the shortest practical lifetime, using provider/domain-native delivery. Avoid command-line arguments. Do not retain a reusable plaintext copy.

Preserve ownership boundaries:

```text
Phase 28 -> development credential consumers
Phase 31 -> service credential consumers
Phase 32 -> storage/LUKS credential consumers
Phase 33 -> network/VPN/Wi-Fi credential consumers
Phase 35 -> repository/package credential consumers
Phase 36 -> configuration references/placeholders
Phase 37 -> secret references/policy/redaction/lifecycle coordination
Phase 38 -> actor/user/service identity + authorization context
Phase 39 -> secret-safe temporal events
Phase 45 -> unified control-plane contracts
```

Lifecycle mutations follow:

```text
observe safe metadata/provider state
 -> resolve stable SecretRef
 -> identify actor + consumer + purpose + scope
 -> capability + policy + dependency/impact analysis
 -> exact lifecycle plan
 -> authorize
 -> immediate provider/ref revalidation
 -> provider-native operation
 -> verify safe postcondition without disclosing material
 -> emit redacted audit/timeline evidence
```

Rotation must account for consumers and cutover. Revocation/deletion must never be inferred from apparent non-use. UNKNOWN is not PASS.

A broken Phase 37 must not destroy access to native keyrings, SSH agents, LUKS recovery, network credentials or other provider-native recovery paths.


## Phase-specific implementation requirements

Implement this phase around the following exact focus:

**Avoid broad plaintext secret caches; where unavoidable, require explicit bounded lifetime and zero general persistence.**

Before implementation, locate all overlapping Rebuntu secret, credential and redaction mechanisms and document whether each is reused, refactored, migrated into Phase 37, adapted through a domain owner, or intentionally retained elsewhere. Do not create a second vault, keyring or credential database.

The common representation must be value-blind by construction. Any provider-specific code that can transiently handle resolved material must be isolated from generic DTOs, persistence, telemetry and semantic context. Every access or lifecycle mutation introduced here must bind to an exact SecretRef, actor/consumer/purpose/scope, provider capability, policy decision, explicit authorization and safe postcondition verification.

Add deterministic tests specific to this focus. Use only synthetic credentials/canary secrets and assert that their exact bytes never appear outside explicitly permitted transient provider/consumer test boundaries.

## Required implementation method

1. **Repository-first discovery.** Produce an ownership/reuse/migration map for all secret/credential/redaction code.
2. **Value-blind common model.** Design common DTOs, persistence and APIs so they cannot serialize a secret value field.
3. **Provider adapters.** Native providers own storage/resolution/lifecycle mechanics; expose only capabilities and safe metadata centrally.
4. **Purpose-bound access.** Secret resolution requires actor, authorized consumer, purpose, scope and narrow delivery path.
5. **Structural redaction.** Apply schema-aware redaction before logs, persistence, audit, timeline, export, search or model handoff.
6. **Lifecycle verification.** Verify provider-side safe status/consumer behavior without returning secret material.
7. **Leak testing.** Use synthetic high-entropy canary secrets and assert their absence from logs, files, databases, serialized DTOs, errors, Panel payloads, timeline, search and model-context fixtures.


## Global acceptance gate

Complete only when:
- existing secret/credential code was audited and ownership reconciled;
- the generic persistent model has no secret-value field;
- native secure providers retain secret custody;
- provider unavailable/locked states never trigger plaintext fallback;
- SecretRefs are stable opaque references with safe metadata only;
- resolution is purpose/consumer/actor scoped and authorization-gated;
- resolved values have bounded lifetime and are not generally cached;
- command-line delivery is avoided for secrets;
- structural redaction occurs before serialization/persistence/indexing;
- logs/audit/config history/timeline/Panel/search/model/agent contexts are secret-value free;
- rotation/revocation/deletion remain separate lifecycle actions;
- orphan detection never auto-revokes/deletes;
- integrations use SecretRefs rather than copied values;
- mutations are planned, authorized, revalidated and provider-verified;
- CLI/Panel cannot reveal values through generic inspection;
- synthetic canary leak tests cover all persistence/output paths;
- native provider recovery remains available without Phase 37;
- unsupported/unverified behavior remains explicit UNKNOWN/deferred.


## Required final report for Phase 37.20

Return:
1. **Discovery & ownership** — existing secret/credential/redaction code reused, migrated or retained elsewhere.
2. **Secret model** — exact SecretRefs, safe metadata, provider and lifecycle states; confirm no generic value field exists.
3. **Provider/capability boundary** — native provider operations and unsupported/locked states.
4. **Implementation** — exact files changed/created/refactored.
5. **Access policy** — actor, consumer, purpose, scope, authorization and delivery path.
6. **Redaction/persistence** — all serialization/log/audit/history/search/model boundaries inspected.
7. **Lifecycle verification** — safe provider-side postconditions without revealing values.
8. **Leak tests** — synthetic canary locations checked and exact results.
9. **Recovery** — native provider access/recovery paths preserved.
10. **Remaining UNKNOWNs** — unsupported or unverified behavior only.

Never print, quote, hash-for-display, partially reveal, persist or include a real secret value in the report. A masked string is not proof that upstream persistence was secret-safe.
