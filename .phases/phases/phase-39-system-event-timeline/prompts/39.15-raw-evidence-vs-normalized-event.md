# Phase 39.15 — Raw Evidence vs Normalized Event

## Mission

Preserve raw evidence references separately from normalized event interpretations.

## Non-negotiable architecture and invariants

The project is always **Rebuntu**. Begin with repository-first discovery and obey applicable AGENTS.md/tree rules. Search for existing journald readers, histories, event buses, audit trails, command history, metrics, incident records and temporal correlation code before adding anything. Reuse, refactor and migrate first. Apply **aggregational morphing**.

Phase 39 is a **temporal evidence plane**, not a replacement for journald, package history, shell history, provider logs, metric stores or domain state. Store normalized events plus durable references/cursors/fingerprints where possible; do not blindly duplicate raw source stores.

Mandatory distinctions:

```text
EVENT != RAW LOG LINE
EVENT != CURRENT STATE
EVENT ARRIVAL TIME != OCCURRENCE TIME
REALTIME != MONOTONIC TIME
MONOTONIC TIME ACROSS DIFFERENT BOOTS != COMPARABLE
PROVIDER ORDER != WALL-CLOCK ORDER
TEMPORAL PROXIMITY != RELATIONSHIP
A BEFORE B != A CAUSED B
CORRELATION != CAUSATION
HYPOTHESIS != OBSERVED EVENT
TIMELINE SUMMARY != SOURCE EVIDENCE
HISTORICAL STATE != CURRENT STATE
MISSING EVENT != PROOF EVENT DID NOT OCCUR
```

Typed relation semantics must remain explicit:

```text
PRECEDES
RELATED_TO
TRIGGERED_BY
CAUSED_BY              # only with strong deterministic/domain evidence
HYPOTHESIZED_CAUSE     # analysis/semantic hypothesis, never promoted silently
```

Every normalized event carries source/provider provenance, host/boot identity where relevant, timestamp semantics/precision, entity refs, evidence refs and epistemic classification.

Wall-clock jumps, NTP corrections, suspend/resume, provider buffering and late arrival must not silently corrupt ordering. Monotonic timestamps are boot-scoped.

Privacy is a first-class architecture boundary. Phase 39 must not become continuous user surveillance. Do not capture arbitrary keystrokes, screen contents, file browsing or unrelated user activity. Shell history is integrated through Phase 26 records and its privacy policy.

Phase 37 redaction happens before timeline persistence/indexing/export/model handoff. Secret material never enters event payloads, indexes, summaries or semantic context.

Preserve ownership boundaries:

```text
domain phases -> authoritative current state + native evidence
Phase 26 -> shell command records
Phase 39 -> normalized temporal evidence + episodes + temporal relations
Phase 42 -> structural knowledge relationships
Phase 43 -> semantic interpretation/hypotheses
Phase 44 -> adaptation policy/outcomes
Phase 45 -> control lifecycle coordination
```

The semantic model may summarize or propose hypotheses from a bounded evidence bundle, but its output is annotation, not source evidence and never becomes `CAUSED_BY` without independent qualifying evidence.

Retention/compaction must account for deleted detail explicitly. Do not claim complete historical reconstruction when events were unavailable, dropped, compacted or never persisted.

A broken Phase 39 must leave journald/native provider histories and conventional Bash diagnostic tools usable.


## Phase-specific implementation requirements

Implement this phase around the following exact focus:

**Preserve raw evidence references separately from normalized event interpretations.**

Before implementation, locate every overlapping Rebuntu event/history/timeline mechanism and document whether it is reused, refactored, migrated into Phase 39, adapted through a domain owner, or intentionally retained as a native evidence provider. Do not create duplicate raw-log or metrics storage merely to make the timeline self-contained.

Every event introduced here must preserve exact evidence refs, provider provenance, boot/time semantics, entity refs and epistemic class. Every derived relationship must state the deterministic rule/evidence supporting it. If only temporal proximity or semantic plausibility exists, represent it as RELATED_TO/HYPOTHESIZED_CAUSE rather than CAUSED_BY.

Add deterministic tests specific to this focus, including out-of-order evidence and incomplete-history behavior where relevant. All privacy/redaction tests must prove sensitive synthetic canaries are absent before persistence and indexing.

## Required implementation method

1. **Repository-first discovery.** Produce an ownership/reuse/migration map for event, history, journal, metric and audit mechanisms.
2. **Temporal correctness.** Model realtime, monotonic, boot identity, provider sequence, precision and uncertainty explicitly.
3. **Evidence preservation.** Normalize events while retaining exact source/evidence references and provider-specific detail access.
4. **Causality discipline.** Never derive causation from ordering/proximity alone; encode hypotheses separately.
5. **Privacy before persistence.** Apply structural redaction/minimization before event serialization, indexing, export or model context.
6. **Bounded storage.** Control cardinality/event storms with explicit loss/coalescing accounting; avoid raw metric/log duplication.
7. **Deterministic disorder tests.** Test clock jumps, late arrival, duplicate events, boot boundaries, partial writes and reindexing with fixtures.


## Global acceptance gate

Complete only when:
- existing event/history mechanisms were audited and ownership reconciled;
- native journals/histories remain authoritative evidence providers;
- realtime/monotonic/provider ordering and boot identity remain distinct;
- clock jumps/suspend/late events do not silently corrupt ordering;
- every event has provenance/evidence refs and epistemic class;
- raw evidence and normalized events remain distinguishable;
- temporal proximity never becomes causality automatically;
- hypotheses remain distinct from observed/causal relations;
- secret redaction/privacy minimization happens before persistence/indexing;
- shell integration does not become keystroke/activity surveillance;
- high-cardinality/event storms are bounded with explicit loss accounting;
- summaries retain supporting event/evidence refs;
- historical reconstruction exposes gaps and uncertainty;
- CLI/Panel/model consumers use typed Phase 39 APIs;
- failure tests cover temporal disorder and persistence/index faults;
- native provider diagnostics remain available without Phase 39;
- unsupported/unverified behavior remains explicit UNKNOWN/deferred.


## Required final report for Phase 39.15

Return:
1. **Discovery & ownership** — existing timeline/history/provider mechanisms reused, migrated or retained.
2. **Temporal model** — timestamps, boot identity, provider order, precision and uncertainty.
3. **Evidence/provenance** — EventRefs, EvidenceRefs, entity refs and epistemic classes.
4. **Implementation** — exact files changed/created/refactored.
5. **Relations/episodes** — exact deterministic rules and evidence; clearly separate hypotheses.
6. **Privacy/redaction** — data minimized and excluded before persistence/indexing/model handoff.
7. **Persistence/retention** — storage/index behavior, loss accounting and historical gaps.
8. **Verification/tests** — disorder, clock, duplicate, storm, corruption and recovery results.
9. **Remaining UNKNOWNs** — unsupported, missing or unverifiable historical facts only.

Never report temporal adjacency, a semantic narrative, a common entity, one preceding command, one log line or one model explanation alone as proof that event A caused event B.
