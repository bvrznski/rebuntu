# Phase 43.2 — Intelligence ownership map

## Objective
Implement **Intelligence ownership map** as a complete production-integrated workstream of Rebuntu Phase 43 — Operator Intelligence System.

## Repository-first execution
Recursively discover/read all applicable `AGENTS.md`, all Phase 43 architecture documents, relevant source/tests/build files and affected Phase 21–42 contracts. Search for existing heuristics, health/risk scoring, anomaly/prediction logic, log semantics, evidence assembly, recommendations and semantic-model integration. Use aggregational morphing: integrate/refactor existing capabilities; never create a parallel intelligence subsystem.

`src/` is the canonical architecture-first tree. Place code under the narrowest stable architectural owner, deepening real domain → subsystem → capability → component structure where justified. Deterministic production functionality is C++-first. Python remains only at explicit semantic/ML/model, research/experimental or narrow justified interoperability boundaries.

## Hard invariants
Phase 43 is decision support, not a second control plane. It may collect evidence, derive supported findings, correlate observations, detect anomalies, form hypotheses/forecasts, explain state, recommend alternatives and construct candidate plans. It may not fabricate observations, silently promote semantic output to fact, authorize consequential actions, bypass Phase 40/domain validation, mutate authoritative state or grant models shell authority.

Preserve `OBSERVED_FACT`, `DETERMINISTIC_DERIVATION`, `SEMANTIC_ANNOTATION`, `HYPOTHESIS`, `RECOMMENDATION`, `UNKNOWN`. Preserve `UNKNOWN != PASS`, `BEFORE != CAUSED_BY`, `graph path != causality`, `correlation != causation`, and `model confidence != factual probability`.

Every material artifact retains evidence refs, provenance, scope, freshness, epistemic class and meaningful uncertainty. Phase 39 remains temporal authority; Phase 40 search/typed-command authority; Phase 41 workflow authority; Phase 42 structural-knowledge authority; domain systems retain domain-state authority.

LLMs/learned models are providers only. Prompt construction, evidence selection, schemas, validation and authority remain Rebuntu-owned. Unsupported model claims stay semantic/hypothetical or are rejected. Never allow model text to manufacture evidence refs.

Never place Phase 37 secret material in prompts, embeddings, caches, artifacts, logs, telemetry, previews or fixtures. Use minimum safe evidence projection and SecretRef.

## Consequential-action boundary
Actionable output becomes a typed Phase 40 candidate plan/intent. Execution still follows:
`observe → plan → validate → authorize → execute → verify → record`.
Re-observe authoritative state where freshness matters.

## Implementation and validation
Define typed contracts, lifecycle, validation, providers, evidence requirements, error/UNKNOWN semantics, persistence/cache behavior, cancellation, resource bounds, observability and provenance. Integrate actual callers, initialization, registries, CMake, packaging, CLI/Panel, tests and cross-phase interfaces. Do not leave native code unused behind a legacy Python path.

Add unit/integration/adversarial tests for insufficient/contradictory/stale evidence, hallucination, provider failure/timeout, UNKNOWN, denial, restart, concurrency and races. Explicitly prove semantic providers cannot execute shell, mutate state, authorize, fabricate evidence or expose secrets. Build/test native code and trace real production paths.
