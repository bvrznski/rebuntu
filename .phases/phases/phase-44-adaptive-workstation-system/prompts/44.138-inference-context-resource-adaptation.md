## Authority and safety invariants
Phase 44 may adapt the workstation only through existing typed domain/control interfaces. It does not replace domain owners, Phase 40 typed command authority, Phase 41 workflow orchestration, Phase 42 structural knowledge or Phase 43 operator intelligence.

The canonical adaptive lifecycle is:

`observe → understand → propose → simulate/plan → validate → authorize → apply → verify → measure outcome → retain/revert`

For consequential mutation, preserve the underlying control lifecycle:

`observe → plan → validate → authorize → execute → verify → record`

Never interpret an adaptive goal, learned preference, recommendation, profile or model output as authorization.

`UNKNOWN != PASS`.
`short-term improvement != proven durable improvement`.
`correlation != causation`.
`learned preference != factual system truth`.
`automatic != unrestricted`.

Protect bootability, storage integrity, network/SSH maintenance access, graphical session, security controls, package trust, secrets and Rebuntu's own control plane. Do not perform destructive experimentation.

Use runtime-discovered topology and durable identities. Never encode transient GPU indices, PIDs or `/dev/sdX` names as durable adaptive identities.

## Adaptive behavior requirements
Every adaptation must have explicit scope, rationale/evidence, expected effect, applicable context, authorization requirement, reversibility classification, measurement criteria, expiry where appropriate and provenance.

Automatic adaptation must be bounded by policy, budgets, allow/deny constraints, cooldown/hysteresis and resource/safety limits. Prevent oscillation, thrashing and self-reinforcing feedback loops.

Where experimentation is appropriate, establish baseline, hypothesis, bounded variables, measurement window, success/failure criteria, abort conditions and rollback before applying the experiment.

Outcome learning must use verified post-change evidence. Preserve failed/neutral outcomes rather than learning only from successes. Operator feedback may shape preferences but must not rewrite observed facts.

Semantic/ML providers may propose contexts, goals, expected effects or candidate adaptations, but cannot authorize, execute, fabricate measurements or weaken safety constraints.

Never expose Phase 37 secret material to semantic prompts, adaptive state, logs, telemetry, history, caches or fixtures. Use SecretRef and minimum safe projections.
