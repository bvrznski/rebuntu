## Objective
Implement **End-to-end partial-failure scenario** as a complete production-integrated workstream of Rebuntu Phase 45 — Unified Control Plane.

## Repository-first execution
Before changing code, recursively discover and read every applicable `AGENTS.md`, every Phase 45 architecture document, relevant implementation/tests/build/packaging/service definitions, and affected contracts from all prior Rebuntu phases. Trace real production entry points, callers, providers and domain owners.

Use aggregational morphing. Phase 45 is architectural convergence: reconcile existing control paths into one canonical plane. Do not create a new manager beside existing managers, a second command bus, a second authorization layer, or a language-defined parallel runtime.

`src/` is the canonical architecture-first implementation tree. Place code under the narrowest stable architectural owner and deepen real domain → subsystem → capability → component structure where justified. Deterministic production runtime/control functionality is C++-first. Python remains only at explicit semantic/ML/model, research/experimental or narrow justified interoperability boundaries.

## Fundamental authority model
Every domain has one authoritative owner. Phase 45 routes, coordinates and standardizes access to those owners; it does not seize their native state.

Preserve:
`intent → resolve authority → observe → plan → validate → authorize → execute → verify → record`

For consequential operations, no stage may be silently skipped.

Search results are not authority.
Graph knowledge is not authority.
Workflow definitions are not authority.
Semantic/model output is not authority.
Recommendations are not authority.
Adaptive goals are not authority.
Cached state is not fresh authoritative observation.
Authorization is not permanent.
Execution success is not verification success.
`UNKNOWN != PASS`.

Phase 39 remains temporal authority; Phase 40 search/typed-command authority; Phase 41 workflow authority; Phase 42 structural-knowledge authority; Phase 43 intelligence authority within its advisory scope; Phase 44 bounded adaptation authority within explicit policy. Domain systems remain authoritative for domain state and native operations.

## Typed-control requirements
Use typed intents, capabilities, observations, plans, validations, authorization decisions, execution attempts and verification results. Preserve provenance, epistemic class, freshness, identity and evidence references.

Never reduce the native action vocabulary to arbitrary shell strings. Any process/shell compatibility boundary must use explicit executable/argv, constrained environment/cwd, timeout/output limits, authorization, validation and audit.

Do not promise exactly-once external side effects or cross-domain ACID transactions when native systems cannot provide them. Represent idempotency, reconciliation, partial success, compensation, rollback and ambiguous outcomes honestly.

Phase 37 secret material must not enter plans, history, logs, telemetry, search/graph indexes, semantic prompts, workflow state or test fixtures. Use SecretRef and least-privilege retrieval boundaries.

## Safety and resilience
Protect bootability, storage integrity, networking/SSH maintenance access, graphical session, security controls, package trust, identity/authorization systems and Rebuntu's own control plane.

Use narrow privileged helpers and typed IPC. Revalidate freshness-sensitive state before mutation. Detect external drift and TOCTOU hazards.

Crash/restart/reboot recovery must reconcile authoritative native state before retry, rollback or compensation. Never infer success merely from an interrupted local state transition.
