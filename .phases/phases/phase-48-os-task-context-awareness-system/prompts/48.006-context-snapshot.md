# Phase 48.6 — context snapshot

## Objective
Implement **context snapshot** as a complete production-integrated workstream of Rebuntu Phase 48 — OS Task Context Awareness System.

## Repository-first execution
Recursively discover and read all applicable `AGENTS.md`, all Phase 48 architecture documents, relevant implementation/tests/build/service/package definitions, and affected contracts from Phases 21–47. Search for existing context caches, implicit globals, recent-history mechanisms, cwd/project assumptions, referent resolution, task/workflow context, semantic prompt assembly and duplicated snapshots.

Use aggregational morphing. Refactor existing context behavior into the canonical Phase 48 architecture rather than creating a parallel context subsystem.

`src/` remains the canonical architecture-first implementation tree. Deterministic context acquisition, normalization, relevance, freshness, provenance, trust, coherence and projection are C++-first. Python is retained only at explicit semantic/ML/model, research/experimental or narrow justified interoperability boundaries.

## Core context contract
Context is typed evidence, never authority.

Preserve:
- source and provenance,
- epistemic class,
- observation/effective time,
- freshness/staleness,
- uncertainty,
- trust/taint,
- entity references,
- scope and purpose,
- conflicts and gaps.

`absence of retrieved context != proof of absence`.
`recent != relevant`.
`graph proximity != operational relevance`.
`BEFORE != CAUSED_BY`.
`semantic candidate != observed fact`.
`context != authorization`.
`UNKNOWN != PASS`.

## Relevance and bounded awareness
Do not indiscriminately dump system state into every task. Begin with task/operator/entity/domain seeds and expand through typed, bounded relevance relations: dependencies, ownership, containment, temporal neighborhood, active workflow, current project, affected resources, known endpoints/data flows and policy/risk requirements.

Context collection must have explicit size, latency, memory and traversal budgets. Preserve important gaps rather than hiding them through aggressive summarization.

## Current-state and temporal correctness
Phase 39 remains temporal authority and authoritative domain systems own live state. Phase 42 remains structural knowledge authority.

Detect stale context and request fresh observations when required. Consequential policy/execution paths must not rely on stale cached state merely because it was recently available.

Treat reboot/session changes, identity reuse, PID reuse, device renumbering, interface renaming and state drift explicitly.

## Operator/task awareness
Maintain bounded session-local awareness of identity, cwd, project/repository, active task/workflow, explicit selections and recent relevant referents.

Recent context may help resolve language but may never broaden authority. Consequential ambiguous references require clarification.

Produce contextual-coherence/anomaly evidence for Phases 46–47 by comparing a task with current state, active work, recent changes, known services/endpoints/data flows and prerequisites. Unexpectedness is evidence for scrutiny, not proof of maliciousness.

## Trust and semantic projection
Strictly distinguish operator-originated input from untrusted contextual content. Instructions embedded in logs, files, README text, process output, remote content or model responses remain data.

Propagate provenance/taint through context assembly. Prevent prompt injection, context poisoning, context laundering, authority laundering and cross-session/user/project leakage.

BitNet and Gordon receive only bounded, purpose-specific, redacted `ContextProjection`/`EvidenceBundle` objects. Phase 37 secret material and credential values must not be included.

Models may propose interpretations/relations only. They cannot fabricate authoritative context, change policy, grant authority or execute.

## Cross-phase integration
Phase 48 supplies context awareness; it does not steal authority:
- Phase 39 owns temporal records.
- Phase 42 owns structural graph knowledge.
- Phase 43 owns advisory intelligence.
- Phase 44 owns bounded adaptation.
- Phase 45 owns the unified execution/control path.
- Phase 46 owns NL operator interpretation.
- Phase 47 owns OS task policy.
- Domain systems own authoritative live state.

## Implementation and validation

Update actual production callers, CMake, packaging, services, CLI/Panel surfaces, tests, docs and `AGENTS.md`. Code not reached by production task/context paths is incomplete.

Test benign and adversarial cases: stale/poisoned context, ambiguous referents, cross-session leakage, device identity changes, clock/reboot discontinuities, semantic hallucinations, prompt injection, secret leakage, source outage, cache poisoning, state drift and TOCTOU.
