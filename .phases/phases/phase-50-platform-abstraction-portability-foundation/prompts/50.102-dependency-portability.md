# Phase 50.102 — dependency portability

## Objective
Implement **dependency portability** as a complete production-integrated workstream of Phase 50 — Platform Abstraction & Portability Foundation.

## Repository-first execution
Read all applicable `AGENTS.md`, every Phase 50 architecture document, and relevant Phase 21–49 contracts. Recursively inspect the actual production call graph before editing. Reuse/refactor/migrate existing structures; never build a parallel portability subsystem.

## Architectural contract
Rebuntu is one product. Platform does not define architecture. The canonical architecture-first `src/` tree contains portable C++ semantics plus narrow native platform/domain providers.

Capabilities are typed and runtime-discoverable and distinguish AVAILABLE, DEGRADED, UNAVAILABLE, UNSUPPORTED, NOT_APPLICABLE and UNKNOWN with provenance. `UNKNOWN != PASS`; unsupported is never silently successful.

Linux is the mature reference platform. Extract Linux-specific mechanisms behind the narrowest correct provider boundary while preserving native behavior, performance, diagnostics, security and recovery. Do not reduce Linux to a lowest common denominator.

Future Windows support must use native Windows providers under the same semantic contracts. Do not implement Windows by translating Linux commands, using WSL as a fake provider, making PowerShell the control plane, creating a separate Windows Rebuntu, or scattering `_WIN32` conditionals through domain logic.

Use domain-oriented providers rather than one giant Platform interface. Providers implement mechanisms; they never authorize actions or expose arbitrary shell authority.

C++ owns deterministic runtime, state, policy, context, platform control and authorization machinery. Python remains only at explicit semantic/ML/model/scientific/research/experimental or narrow justified interoperability boundaries.

## Security and integration
Preserve Phase 45 execution authority, Phase 47 policy, Phase 48 context, Phase 37 secret handling and all prior domain ownership. Privilege remains narrow, typed and platform-native.

Migrate real production callers to the new boundary. Update CMake, includes, namespaces, packaging, services, CLI/GUI, tests, docs and `AGENTS.md`. Do not retire Linux implementations before parity and caller migration are verified.

## Validation
Add portable-core, provider-contract, capability-state, degraded/failure/UNKNOWN and Linux regression tests. Add architecture checks preventing new platform leakage and arbitrary shell fallbacks.

## Fixed-point closure
Rediscover the entire repository after implementation for Linux paths/APIs/commands, POSIX assumptions, platform macros, duplicate providers, shell fallbacks, privilege bypasses and stale Python ownership. Resolve all findings and repeat. Require a second clean pass and an adversarial portability/capability/privilege audit.

The repository, not this prompt inventory, defines completion.
