## Non-negotiable invariants

- THIS PROJECT IS REBUNTU; there is exactly one Rebuntu architecture.
- REBUNTU IS C++-NATIVE.
- Extend the canonical architecture in place; do not build a parallel subsystem.
- SEARCH BEFORE IMPLEMENTING; COMPOSE BEFORE GENERATING; UNDERSTAND BEFORE MODIFYING.
- DATA != CONTROL.
- MODEL OUTPUT != AUTHORITY.
- CONTEXT != AUTHORITY.
- TRUST != EXECUTION AUTHORITY.
- PRIVILEGE != INTEGRITY.
- AUTHENTICATION != AUTHORIZATION.
- UNKNOWN != PASS.
- PLAN != AUTHORIZATION != EXECUTION.
- EXPECTED EFFECT != OBSERVED FACT.
- Phase 45 remains the canonical control plane; Phase 47 task policy and Phase 53 mandatory security remain non-bypassable.
- Phase 54 capability/affordance evaluation does not authorize action; Phase 55 planning does not authorize action.
- C++ owns deterministic runtime/state/control/validation/graph/reconciliation/recovery mechanics.
- Python/model services may propose semantic candidates only at explicit boundaries.
- No system(), popen(), sh -c or bash -c as canonical architecture.
- Use typed operations and exact strong target identities.
- Freshness, provenance, uncertainty and UNKNOWN are first-class.
- Timeout/cancellation/crash never prove no side effect.
- Retry != replay permission; compensation != rollback; no exactly-once fiction.
- Bound queues, graphs, retries, histories, caches, recursion, concurrency and resource use.
- Use C++20, RAII, strong types and explicit ownership; no raw owning pointers.
- No giant Manager/Controller/God object.
- Native Linux mechanisms remain authoritative for state/mechanics they own.
- Do not hard-code the developer workstation topology.
- Do not destructively mutate the host merely to satisfy tests.
- Production code must be build- and runtime-reachable.
- Migrate callers to a fixed point before retiring obsolete paths.
- Documentation must describe implemented reality.
- Rebuntu evolves through aggregational morphing: discover → extend → compose → refactor → migrate → remove obsolete duplication.
