## Non-negotiable invariants

- THIS PROJECT IS REBUNTU; there is exactly one Rebuntu architecture.
- REBUNTU IS C++-NATIVE.
- C++ owns authoritative deterministic runtime, state, lifecycle, concurrency, validation, control and native OS mechanics.
- Python is restricted to explicit semantic, ML, research, testing and development boundaries.
- Search before implementing; extend, compose and refactor before adding parallel structures.
- Migrate callers to a fixed point before retiring obsolete active paths.
- DATA != CONTROL.
- MODEL OUTPUT != AUTHORITY.
- CONTEXT != AUTHORITY.
- TRUST != EXECUTION AUTHORITY.
- PRIVILEGE != INTEGRITY.
- AUTHENTICATION != AUTHORIZATION.
- UNKNOWN != PASS.
- EXECUTION SUCCESS != VERIFIED SUCCESS.
- EXPECTED EFFECT != OBSERVED FACT.
- PLAN != AUTHORIZATION != EXECUTION.
- Capability != permission; affordance != authorization.
- Native Linux mechanisms remain authoritative where applicable.
- Providers provide mechanisms/evidence, not authorization.
- No system(), popen(), sh -c, bash -c or generated shell strings as canonical authority.
- Use C++20, RAII, strong types, explicit ownership and no raw owning pointers.
- Bound queues, graphs, histories, retries, recursion, concurrency and resource use.
- Cancellation != rollback; compensation != rollback; retry != replay permission.
- Timeout/crash/interruption never prove no side effect.
- No false ACID or exactly-once claims.
- Freshness, provenance, uncertainty and UNKNOWN are first-class.
- Cache/index/history/model output never silently become live authority.
- Names, paths, PIDs, GPU indices and IPs are not automatically durable identities.
- Mutation converges through observe → plan → validate → authorize → execute → verify → record.
- Phase 45 control plane, Phase 47 task policy and Phase 53 mandatory security remain non-bypassable.
- Phase 54 capability/affordance and Phase 55 planning remain non-authoritative.
- Secret material must not enter generic logs/prompts/graphs/diagnostics.
- No giant Manager/Controller/Registry/God object.
- Production code must be build- and runtime-reachable.
- Tests cover negative/failure/restart/race/adversarial behavior.
- Do not destructively mutate host/user data for tests.
- Documentation and AGENTS.md describe implemented reality.
- Use aggregational morphing, not parallel bolt-ons.
