**Status:** ACCEPTED

## Executive Summary

This discovery establishes the canonical C++ native forms module for Rebuntu Phase 1.3, providing structured input collection and validation functionality for installation and setup workflows.

## Problem Statement

Phase 1.2 established installation planning but left structured user input incomplete:

- Forms implementation existed in `src/portability/install/forms.hpp` with enhanced features
- Simpler implementation existed in `src/system/install/forms.hpp`
- No canonical canonical location for forms module
- Tests used inconsistent include paths

Key requirements from Phase 1.3:
1. Consolidate duplicate forms implementations
2. Provide input channels for interactive and non-interactive modes
3. Support comprehensive validation (types, ranges, paths)
4. Enable unknown field detection in config files

## Canonical Architecture

### Forms Flow

```
User/CLI/API Intent
    ↓
InputChannel (InteractiveInputChannel / ConfigFileChannel)
    ↓
FormParser.parse()
    ↓
FormResult with validated FieldResults
    ↓
InstallationIntent / Configuration
```

### Core Types

```cpp
// FormDefinition - Schema for form structure
struct FormDefinition {
    std::string name, title, description;
    bool is_interactive = true, requires_all_fields = true;
    std::vector<FieldDefinition> fields;
};

// FieldDefinition - Individual field configuration
struct FieldDefinition {
    FieldMetadata metadata;
    FieldType type = FieldType::kString;
    std::vector<FieldConstraint> constraints;
    std::optional<std::vector<std::string>> allowed_values;
    std::optional<std::any> default_value;
};

// InputChannel - Abstract input source interface
class InputChannel {
public:
    virtual ~InputChannel() = default;
    virtual std::vector<std::string> available_fields() const = 0;
    virtual bool has_field(std::string_view name) const = 0;
    virtual std::optional<std::string> try_get_string(std::string_view name) const = 0;
    virtual std::map<std::string, std::string> all_values() const = 0;
};

// FormParser - Parses and validates form data
class FormParser {
public:
    explicit FormParser(const FormDefinition& def);
    FormResult parse(const InputChannel& channel) const;
};
```

## Validation Features

### Type Validation
- `kString` - Free text
- `kInteger` - Parses to int64_t with trailing character detection
- `kBoolean` - true/false/yes/no/1/0 case-insensitive

### Constraint Validation
- `kRequired` - Field must be present or have default
- `kMinLength` / `kMaxLength` - String length bounds
- `kAllowedValues` - Enum-like validation
- `kPathExists` - Filesystem path must exist
- `kPathIsDirectory` - Path must be a directory
- `kPathIsFile` - Path must be a regular file

### Semantic Validation
- Unknown field detection in input
- Empty value rejection with kNotEmpty constraint
- Invalid type parsing errors reported per-field

## Key Design Decisions

1. **Consolidation Strategy**: Moved enhanced portability version to canonical location `src/system/install/forms.hpp`
2. **C++ Standard Compatibility**: Used `find() != end()` instead of `contains()` for map/set operations
3. **Input Channel Pattern**: Abstract interface allows multiple input sources without modifying parser
4. **Validation Separation**: Parsing and validation are distinct phases in FormParser
5. **Error Reporting**: Per-field errors allow partial form processing with warnings

Indirect integration points:
- Host discovery produces facts used as form defaults
- Installation intent forms feed into planning

## Known Limitations

1. **Path Validation**: Uses `std::filesystem` - requires valid filesystem paths during validation (not suitable for dry-run)
2. **No Secret Masking**: Sensitive fields tracked via metadata but not masked in output
3. **C++ std::any**: Runtime type information may be lost; future type-safe alternatives possible
